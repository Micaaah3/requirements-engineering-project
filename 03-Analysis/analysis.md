# Is it actually a requirement?

## Problem / Observation
- People are sometimes unsure whether a camera is available

## Stakeholder need / concern
- Technicians need to know what equipment is due back
- A lecturer wants reliable availability information before promising equipment

## Candidate requirement
- The system shall record the expected return date for each booking.

## Solution Idea
- The college should build a mobile app

## Assumption
- We assume all users will have a college login.


# Requirements Surgery

## Requirement 1
"The system shall be user-friendly"

### Find
The system should be quick to learn, and easy to use.

### Diagnose
The requirement is generally way too vague
What does "user friendly" look like?

### Ask
What would user-friendly look like to you?

### Repair
"The system should be easy to learn for most people, everything should be labelled neatly."

### Check
What makes the previous system be un user-friendly?
Who will use it the most?
How will we know if it's actually user-friendly?
